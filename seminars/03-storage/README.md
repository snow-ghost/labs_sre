# Семинар 3 Производительность дисков

Практикум по fio, iostat и LVM. В демонстрационном режиме каждый этап выполняется отдельно: сначала показать исходник, затем запустить его и разобрать вывод. Этапы привязаны к слайдам 37-45 презентации ЛК5; весь семинар занимает слайды 34-49. Презентация предоставляется на занятии отдельно.

## Подготовка компьютера

Стенд собирает минимальную Linux-ВМ из пакетов Ubuntu и утилит хоста. Он рассчитан на Ubuntu 24.04 x86_64 и Python 3.12. Требуются доступ к `/dev/kvm`, не менее 5 ГиБ доступной оперативной памяти и 20 ГиБ свободного места. Гостевая машина получает 4 ГиБ памяти, два виртуальных процессора и новый разреженный диск размером 16 ГиБ.

На новом компьютере установите зависимости:

```bash
sudo apt update
sudo apt install git qemu-system-x86 qemu-utils busybox-static cpio zstd curl \
  fio lvm2 thin-provisioning-tools sysstat util-linux kmod e2fsprogs python3.12
```

Пакет fio в этом списке также устанавливает библиотеки, необходимые для его запуска. Сборщик распаковывает пакет fio для гостевой машины, а необходимые библиотеки берет из пакетов и системы хоста. Установка зависимостей требует прав администратора; сам стенд запускается от обычного пользователя.

При первой сборке нужен доступ хоста к `archive.ubuntu.com`. Пакеты скачиваются в `cache/`, их SHA256 сверяется с локальными метаданными APT. Кеш не включен в репозиторий. Должны быть доступны пакет `linux-image-<версия текущего ядра>` в APT и соответствующие модули в `/lib/modules/`. Поддерживаются модули `.ko` и `.ko.zst`. Ядра другого поставщика или другого дистрибутива могут потребовать адаптации.

Из каталога этого семинара выполните:

```bash
bash check.sh
```

Если нет доступа к `/dev/kvm`, проверьте группы пользователя командой `id` и права устройства командой `ls -l /dev/kvm`. При необходимости администратор добавляет пользователя в группу:

```bash
sudo usermod -aG kvm ИМЯ_ПОЛЬЗОВАТЕЛЯ
```

Подставьте фактическое имя и заново войдите в систему. Не запускайте весь стенд через `sudo` и не открывайте устройство KVM для записи всем пользователям.

## Пошаговый показ

В обычном терминале, из каталога семинара:

```bash
bash demo.sh
```

Появится приглашение `СМ3>`. До занятия выполните подготовку:

```bash
show 0
run 0
```

Этап 0 заполняет файл размером 2 ГиБ, проверяет движок io_uring и сохраняет контрольную сумму файла. Дождитесь кода 0 и оставьте консоль открытой.

На занятии выполняйте этапы по одному:

```bash
show 1
run 1
show 2
run 2
```

`show` только печатает исходник с номерами строк. `run` выполняет выбранный скрипт, показывает вывод и возвращает управление преподавателю. Следующий этап автоматически не запускается. Команда `steps` показывает список, `show_fn sm3_fio` раскрывает исходник общей функции с параметрами fio.

| Этап | Слайд | Содержание |
|---|---|---|
| 0 | До занятия | Файл 2 ГиБ, проверка fio и io_uring |
| 1 | 37 | Версии, память, файловая система и устройства |
| 2 | 38 | Фоновая активность iostat, pidstat и журнал ядра |
| 3 | 39 | Два буферизованных чтения и прямое чтение, по 45 секунд |
| 4 | 40 | Глубины 1, 4, 16, 64; по 5 секунд прогрева и 30 секунд измерения |
| 5 | 41 | Сравнение результатов и контрольная сумма файла |
| 6 | 42 | Образ, группа LVM, пул 3 ГиБ и тонкий том 8 ГиБ |
| 7 | 43 | Data%, Meta%, свободное место и параметры расширения |
| 8 | 44 | Снимок пустого тонкого тома |
| 9 | 45 | Проверки принадлежности, удаление и отсоединение образа |

При удалении активных томов на этапе 9 вводите `y` вручную после проверки имен. После очистки команда `finish` выключает ВМ и сохраняет результаты на хосте. Подробности показа и разбор ошибок: [памятка](ДЕМОНСТРАЦИЯ.txt).

## Проверка перед занятием

```bash
bash run.sh       # Полный автоматический прогон fio и LVM
bash run-lvm.sh   # Только автоматическая проверка LVM
```

В автоматическом режиме подтверждения удаления учебных томов заданы в сценарии. Для показа студентам используется `demo.sh`, где подтверждения остаются ручными. Одновременные прогоны блокируются.

## Результаты и ошибки

Каждый запуск создает новый каталог `runs/run-XXXXXXXX`. В начале работы выводится его точный путь. `serial.log` содержит журнал, `results/` содержит извлеченные JSON, файлы времени и статистику iostat. В полном автоматическом режиме дополнительно формируется `results/summary.txt`.

Полный автоматический прогон завершается сообщением `ПРОВЕРКА ПРОЙДЕНА`. В демонстрационном режиме оценивайте код каждого этапа: 0 означает успех, 130 означает прерывание через Ctrl+C. Частичный показ не объявляется полным успешным тестом. Результат без завершающей отметки `exit=0` исключается из демонстрационной таблицы.

Повторная запись результатов под тем же именем запрещена. При ошибке LVM сначала выясните фактическое состояние объектов. Повторять создание или удаление наугад нельзя. Порядок восстановления описан в [тексте семинара](seminar-source.md).

Новый запуск создает новый диск; продолжение старого сеанса не предусмотрено. Старый образ нельзя самостоятельно загружать через подготовленный загрузчик: при загрузке он форматирует учебный диск. Файлы прогона автоматически не удаляются.

## Изоляция и ограничения

ВМ не получает диски хоста, общие каталоги и сетевой интерфейс. Команды изменения LVM выполняются внутри ВМ, а результаты извлекаются из выключенного образа через debugfs без его монтирования. Нагрузка fio использует реальные ресурсы компьютера и может повлиять на другие приложения.

В минимальной ВМ нет systemd и dmeventd. Вместо journalctl показывается dmesg. Параметры авторасширения можно прочитать, но работа службы не демонстрируется. Тонкий том в обязательном опыте пуст: влияние изменений блоков снимка разбирается по учебной модели. Результаты fio характеризуют гостевую систему при текущем состоянии хоста.

## Состав файлов

- `demo/00-*.sh` - `demo/09-*.sh`: скрипты этапов, копируемые в `/demo` внутри ВМ.
- `demo/common.sh`: защитные проверки и общие функции.
- `demo/results.py`: извлечение и проверка результатов fio.
- `build_demo.py`: сборка общих функций из `seminar-source.md`.
- `vm.py`: сборка, запуск ВМ и извлечение результатов.
- `seminar-source.md`: полный текст проведения и исходные команды семинара.

Не запускайте скрипты из `demo/` напрямую на хосте. Открывать их в редакторе можно. Изменения файлов хоста попадают в ВМ при следующем запуске `demo.sh`. Генерируемый `common.sh` изменяется через источник и `build_demo.py`.

Справочные источники по fio, iostat и LVM перечислены в конце текста семинара.
